## 适合谁

要自己写后端、脚本、Bot 或小工具，**直接 HTTP 调模型**，而不是用 Cherry / Claude Code / Cursor 这类现成客户端。

前提：

1. 已有 Base URL 与 API Key（见 [创建 API Key 与分组](/getting-started/create-key/)）  
2. 知道要用的模型名 `{{MODEL_NAME}}`（与定价页完全一致）  
3. 先弄清协议：见 [协议说明](/reference/protocols/)  

连通性可先跑 [验证页的 curl](/getting-started/verify/)。字段级 OpenAPI 以你网关文档为准；兼容 [New API](https://docs.newapi.pro/zh/docs/api) 一类网关时，下文端点与认证方式与其 AI 模型接口一致。

## 地址与认证

OpenAI 兼容调用通常把客户端 `base_url` / `baseURL` 设为：

```text
{{API_BASE_URL}}/v1
```

请求头（多数 OpenAI 风格接口）：

```http
Authorization: Bearer sk-你的密钥
Content-Type: application/json
```

注意：

- **不要**把 `.../v1/chat/completions` 整段塞进 Base URL（除非你自己拼完整 URL）  
- Claude 原生接口除 Bearer 外，还需 `anthropic-version`；也可用 `x-api-key`  
- Gemini 原生可用查询参数 `key=` 或请求头 `x-goog-api-key`  
- Key 等同密码：不要写进公开仓库、截图、日志  

## AI 调用端点一览

仅列**模型调用**相关路径（不含后台管理接口）。服务端是否开通某能力，以你的分组 / 渠道为准。

| 能力 | 方法与路径 | 说明 |
| --- | --- | --- |
| 聊天补全 | `POST /v1/chat/completions` | OpenAI Chat Completions；需 `model`、`messages`；支持 `stream` |
| Responses | `POST /v1/responses` | OpenAI Responses；支持工具、推理等 |
| 文本补全 | `POST /v1/completions` | 传统补全；需 `model`、`prompt` |
| Claude Messages | `POST /v1/messages` | Anthropic 格式；需 `anthropic-version`、`max_tokens` |
| Gemini 原生 | `POST /v1beta/models/{model}:{action}` | 如 `generateContent`、`streamGenerateContent` |
| Gemini 兼容 | `POST /v1/models/{model}:{action}` | `/v1` 前缀的 Gemini 风格 |
| 嵌入 | `POST /v1/embeddings` | 需 `model`、`input` |
| 重排序 | `POST /v1/rerank` | 需 `model`、`query`、`documents` |
| 内容审核 | `POST /v1/moderations` | 文本等安全检查 |
| 图像生成 | `POST /v1/images/generations` | 文生图 |
| 图像编辑 | `POST /v1/images/edits` | 图生图 / 编辑 |
| 语音转文字 | `POST /v1/audio/transcriptions` | Whisper 等 |
| 音频翻译 | `POST /v1/audio/translations` | 识别并译成英文文本（OpenAI 风格） |
| 文字转语音 | `POST /v1/audio/speech` | TTS |
| 实时语音 | `GET /v1/realtime`（WebSocket） | 如 `wss://主机/v1/realtime?model=...` |
| 视频生成 | `POST /v1/video/generations` | 异步任务，返回 `task_id` 后再查状态 |
| 模型列表 | `GET /v1/models` | 默认 OpenAI 格式；带 Anthropic / Gemini 头时返回对应格式 |
| 模型详情 | `GET /v1/models/{model}` | 不存在时常见 `model_not_found` |

网页游乐场专用 `POST /pg/chat/completions` 依赖登录会话，**不适合**自己封装的服务端调用，请用 `/v1/...`。

## 聊天补全（最常用）

`POST {{API_BASE_URL}}/v1/chat/completions`

常见字段：`model`、`messages`（必填）；`temperature`、`top_p`、`max_tokens` / `max_completion_tokens`、`stream`、`tools` 等可选。

    model="{{MODEL_NAME}}",

    delta = chunk.choices[0].delta.content or ""

package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"net/http"

func main() {
	body := map[string]any{
		"model": "{{MODEL_NAME}}",
		"messages": []map[string]string{
			{"role": "user", "content": "你好，请只回复：配置成功"},
		},
	}
	b, _ := json.Marshal(body)
	req, _ := http.NewRequest(
		"POST",
		"{{API_BASE_URL}}/v1/chat/completions",
		bytes.NewReader(b),
	)
	req.Header.Set("Authorization", "Bearer sk-你的密钥")
	req.Header.Set("Content-Type", "application/json")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		panic(err)
	}
	defer resp.Body.Close()
	out, _ := io.ReadAll(resp.Body)
	fmt.Println(string(out))
}
```

// 依赖：com.openai:openai-java（版本以 Maven Central 为准）
import com.openai.client.OpenAIClient;
import com.openai.client.okhttp.OpenAIOkHttpClient;
import com.openai.models.ChatModel;
import com.openai.models.chat.completions.ChatCompletionCreateParams;

OpenAIClient client = OpenAIOkHttpClient.builder()
    .apiKey("sk-你的密钥")
    .baseUrl("{{API_BASE_URL}}/v1")
    .build();

var params = ChatCompletionCreateParams.builder()
    .model("{{MODEL_NAME}}")
    .addUserMessage("你好，请只回复：配置成功")
    .build();

var completion = client.chat().completions().create(params);
System.out.println(completion.choices().get(0).message().content());
```

## 其他协议与能力（精简示例）

### OpenAI Responses

`POST {{API_BASE_URL}}/v1/responses` — Codex 等新链路常用。

```bash
curl {{API_BASE_URL}}/v1/responses \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "{{MODEL_NAME}}",
    "input": "你好，请只回复：配置成功"
  }'
```

### Claude Messages

`POST {{API_BASE_URL}}/v1/messages` — 需 `anthropic-version`；`max_tokens` 必填。

```bash
curl {{API_BASE_URL}}/v1/messages \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "x-api-key: sk-你的密钥" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "{{MODEL_NAME}}",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

Python（Anthropic SDK）：

```python
from anthropic import Anthropic

client = Anthropic(
    api_key="sk-你的密钥",
    base_url="{{API_BASE_URL}}",
)
msg = client.messages.create(
    model="{{MODEL_NAME}}",
    max_tokens=1024,
    messages=[{"role": "user", "content": "你好"}],
)
print(msg.content)
```

## 流式输出注意点

- Chat Completions：`"stream": true`，响应为 **SSE**（`data: {...}` 行，结束常见 `data: [DONE]`）  
- 自封装时请按行解析，不要当整段 JSON `JSON.parse` 一次  
- 反向代理 / CDN 可能缓冲 SSE，需关闭缓冲或设合适超时  
- Responses / Claude / Gemini 的流式字段与事件名不同，按对应协议解析  

## 自检清单

1. Base URL 是否为 `{{API_BASE_URL}}` 或 `{{API_BASE_URL}}/v1`（按协议）  
2. Key 是否完整、已启用、分组含该模型  
3. 模型名是否与定价页一致  
4. Claude 是否带了 `anthropic-version`  
5. 流式客户端是否按 SSE 读  

仍失败时对照 [FAQ](/faq/) 与 [协议说明](/reference/protocols/)。
