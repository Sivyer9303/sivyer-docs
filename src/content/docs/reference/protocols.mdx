## 为什么要懂协议

同一网关往往同时兼容多种协议。选错协议或路径，会出现 404、Invalid JSON、鉴权失败等。

## 常见协议

### OpenAI Chat Completions

- 路径常见：`/v1/chat/completions`  
- 适用：Chatbox、多数插件、Cursor（兼容模式）、很多机器人  
- 客户端通常填：`{{API_BASE_URL}}/v1`

### OpenAI Responses

- 部分 Codex / 新 OpenAI 链路使用  
- 若网关只提供 Chat Completions，可能需要 CC Switch Local Routing 做转换  

### Anthropic Messages

- 适用：Claude Code 等  
- 常见环境变量：`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`  
- Base URL 多为根地址 `{{API_BASE_URL}}`

### Gemini

- 适用：Gemini CLI、部分对话客户端  
- 字段名随客户端变化，优先用 CC Switch  
- **Cherry 4K 生图**另见下一节「Gemini 对话生图」  

### OpenAI Images

- 路径常见：`/v1/images/generations`  
- 典型模型：`gpt-image-1`、`gpt-image-2`  
- 适用：Cherry Studio **「绘画」** 页  
- 需将模型端点类型设为 **图像生成（OpenAI）**；**不要**当助手对话模型用  

### Gemini 对话生图（含 4K）

- 在对话 / 多模态链路里出图，常用自定义参数 `imageConfig.imageSize`（`1K`/`2K`/`4K`）  
- 适用：Cherry **助手**；端点保持对话类，不要设成「图像生成（OpenAI）」  
- 步骤见 [Cherry Studio 生图](/clients/cherry-studio-image/)  

## 工具 → 协议（速查）

| 工具 | 更常走的协议 |
| --- | --- |
| Claude Code | Anthropic |
| Codex | OpenAI Responses（或经转换） |
| Cursor / Chatbox | OpenAI Chat |
| Cherry 聊天 | NewAPI 多协议 |
| Cherry 绘画 | OpenAI Images（`gpt-image-*`） |
| Cherry 助手 4K 生图 | Gemini 对话生图 + `imageConfig` |
| OpenClaw / Hermes / OpenCode | 多为 OpenAI 兼容或由 CC Switch 写入 |

## 填写 Base URL 的经验法则

1. 先试根地址 `{{API_BASE_URL}}`  
2. 客户端若写明 OpenAI Compatible，再试 `{{API_BASE_URL}}/v1`  
3. **永远不要**把完整的 `/chat/completions` 粘进 Base URL（除非工具明确要求完整 URL 模式）
